# 产品概览

Last updated: 2026-11-20

当前需求基线：[大学生机会探索与决策支持：需求分析 v1.0](requirements-handoff.md)。本文概括已确认的产品决定；[需求基线](requirements.md)维护 N 编号，待办在 [GitHub Issues](https://github.com/114August514/campus-lumen/issues)。

## 产品定位

项目名为 **Campus Lumen**（2026-10-22 由 Campus Agora 更名），仓库名为 `campus-lumen`。帮大学生跨机构发现科研、实习、竞赛、交流等机会，看懂实际任务与条件，自主决定下一步。

面向大学生个人的机会探索与决策支持工具，初期服务科大学生。汇集跨机构、跨地区和跨学科的信息，帮助发现选项、理解实际内容、比较适配性，并按需找到准备重点与资源入口。

研究覆盖科研、升学、实习、竞赛、交流、活动通知和学习支持。首个深入案例是人工智能与数据科学学院学生的 AI／软件导师探索。参与机会的目的可以是兴趣、共同参与、认定、学习、研究或就业，可以并存，也会改变。

## 当前产品：统一机会探索

所有机会类型共用“探索 → 发现 → 处理”流程（2026-10-29 确认）。选导师的资料最深；实习、交流、竞赛、资源与支持等使用现有整理入口，是否补充资料深度见 #37。

导师示例覆盖校内外、研究所及海外来源，本科进组、短期科研／访问和研究生导师途径分开表达。已有资料和本次实际读取的正文分别标注；历史项目标为历史，不显示为当前开放。

用户可保存多个探索主题：每个主题保留对象、依据、决定、私人理由和待问；公共资料可复用，私人判断相互隔离。保存在同一浏览器 profile 和同一 `127.0.0.1:5173` origin，不跨设备。

补查保留正文、与问题的联系、来源和时间；重复读取去重，冲突与身份不明的内容待核。查找可中止，有每轮上限，停止后保留已取得的结果；误合并可拆分，关联不明时由用户确认。

AI 整理默认使用界面明确标注的本地模拟服务；服务端配置 Key 后，用户可在每次发送前改选中国科大词元计划。个人内容默认不选，只发送用户逐条勾选的片段；超时显示“可能已发送”。词元计划的平台保留条款、额度归属和团队 Key 用法见 #29，输出质量评估见 #31。

## 产品侧重点与内容深度

| 层次 | 提供的帮助 | 最小深度 |
| --- | --- | --- |
| 核心：发现、理解和比较 | 从当前问题认识选项，理解研究／任务、条件、经历依据与差异 | 足以决定是否继续了解；不要求所有用户都做深入比较 |
| 按需：准备指导 | 说明基础、准备重点、理由与可选路径 | 不做概念教学、练习批改或学习测评 |
| 按需或直达：资源 | 找到课程、算力、文献、设备、咨询等适用支持 | 说明用途、关键前提和获取入口 |

科研场景重点帮助理解跨机构信息与本校选项。地域或学校身份不代替适配判断。办理回到原平台，具体研究工作和项目招收情况分别表达。

## 实际情况考察

介绍之外的实际参与情况是各类机会共同的需要。有经历、记录或知情者入口时，呈现来源、关系、角色和时期；联系入口只展示公开用于相关交流或经本人同意的。缺少资料时帮助明确疑问和进一步了解的途径，不编造经历。

不同年份与团队的经历分开，来源冲突保留背景，私人判断不公开。不以论文数量推断指导品质，不做人格评分或黑红榜。只想查入口的用户可以直接结束。

## 自主选择与可选帮助

浏览、收藏和符合资格都不等于必须参与。用户可以暂停、改变目标或拒绝，无须说明理由。准备与资源按需出现，没有年级压力、欠缺清单、社会比较或默认提醒。

兴趣、娱乐与认定可以同时成立；综测按院系与适用年度规则判断，奖项、学分／GPA 和综测分别表达。官方义务与可选建议分开。衡量标准是任务是否清楚、问题是否解决，而不是使用量。

## 信息供给

已有资料复用与外部补查结合：程序执行固定操作；公开发现使用有限搜索和官网直读，关键词搜索常遇验证页，改进见 #24。

自动化负责主要的收集和整理，团队负责关键核对、异常处理和纠错；可以用文件改错，不需要先建后台。2026-11-19 起团队收集资料时可以登录小红书、BOSS 直聘、LinkedIn、B站等平台，只读，不发帖、评论、关注、私信或联系他人；登录状态只留在收集工具里，收集结果经批次审核后进入资料库。面向学生的服务只读公开页面，不使用学生的平台账号。工具与账号在 #40 试用中确定，收集流程见 `tools/skills/opportunity-discovery/SKILL.md`。

## 进展

2026-10-04 至 10-29 接通了公开正文读取、同源多主题、来源绑定比较、官网补查、主题条件编辑、流式进度、中止与上限、统一 hash 路由和模拟整理；2026-10-31 接入词元计划，两次真实调用分别用时 58 秒和 35 秒（第二次缩短了输出）。中期 demo 已于 PR #21 合入 main。验收结果见[测试报告](../project/test-report.md)；还没有做学生试用（#32），后续工作见 GitHub Issues。

## 界面与数据边界

前端只用 [Primer 体系与视觉规范](ui-system.md)，所有类型共用[前端设计 v1.1](frontend-design.md)的流程。保存、删除、公开查询和 AI 整理的数据边界见[隐私说明](privacy.md)：两种整理服务都只接收本次公开依据和用户勾选的个人片段，后端不保留请求或响应正文。
