# 选导师指南：任务与信息结构设计

Last updated: 2026-10-31

状态：v0.4 任务与信息结构依据。2026-10-04 至 10-22 已接通首轮查找、多会话保存、两候选比较、官网补查回填、主题条件编辑、流式正文、中止与声明上限；§8.7 记录并排比较和 session 式组织，误合并修正机制已进入整合分支。2026-10-29 的[前端设计 v1.1](frontend-design.md)把所有机会类型统一为“探索 → 发现 → 处理”；2026-10-31 整理服务增加词元计划可选 provider，默认与回退仍为明确标注的模拟服务。尚无学生收益或输出质量结论。

选导师仍是内容最深的任务样例；所有机会类型复用同一前端流程，其他类型沿用现有整理入口，不新增调研采集。用户可从任意环节进入，也可在获得一个入口后结束。

## 1. 任务设计的起点

设计单位是“学生想完成的一件事”，不是页面、聊天轮次或功能列表。每项任务说明触发、所需结果、最短操作、系统响应、异常恢复和自然结束位置，再由此推导界面与开发工作。

本轮沿用以下已确认边界：

- 发现和判断共同支持自主选择；不要求完成整条流程、填写完整画像或先创建主题。
- 本校与外校导师使用同一框架。本科科研、短期研究／访问、研究生导师探索是不同参与目的，不能混成一种招生状态。
- 个人可以保留多个探索主题。主题保留问题、偏好、候选、依据、私人理由和待问项；它不等于一个聊天窗口。
- 复用已整理资料，也实际搜索、读取外部来源。可复用调研说明、执行工具和AI判断配合工作；具体供应商和框架留到技术设计。
- 经历与联系入口辅助了解实际情况；保持来源、关系和时期，不生成导师人格排名或自动联系。
- 历史资料可以帮助探索；名额、当年招募和个人资格分别判断。找到信息、换方向、暂缓或停止都可以是有效结果。

准备说明保持在重点、理由和可选路径；资源可以直接查询。其他机会类型留在整体需求研究范围，暂不据此增加首版完整业务流程。

## 2. 六项用户任务

T编号只用于本设计的追溯，不替代[需求基线](requirements.md)中的N编号，也不代表六个独立页面。

| 任务 | 何时进入 | 用户想得到什么 | 最短操作与结束位置 | 对应需求 |
| --- | --- | --- | --- | --- |
| T1 从兴趣发现 | 只有“AI、软件、系统”等兴趣，或想看看还有哪些方向 | 获得可继续了解的研究问题和人物，并知道为何相关 | 输入问题 → 阅读结果／作品；看见一个有意思的方向就可以结束，无需收藏或申请 | N01—N04、N08 |
| T2 补查已知对象 | 已知导师、团队、作品，或有一个尚未确认的问题 | 补上研究、参与途径或条件的关键信息，分清确定与未知 | 找对象 → 看依据 → 按需补查；获得答案或明确仍待确认即可结束 | N02—N04、N08 |
| T3 按当前问题比较 | 有两个或更多候选，不知道差别或参与方式 | 看懂与自己当前问题有关的差异、依据和未知 | 加入比较 → 选看研究或参与途径；可以保留、排除、换目标或不作决定 | N03—N05、N08、N11 |
| T4 进一步了解与准备 | 介绍不足以判断，或不知道怎样迈出下一步 | 找到合适交流路径，或理解准备重点及可用支持 | 从详情选择经历／联系／准备；打开入口、留下一个问题或决定暂缓即可结束 | N06—N08、N11 |
| T5 保存并恢复探索 | 想保留候选及理由，或回来继续上次的问题 | 不重做整理即可恢复判断，多个目的不混在一起 | 保存到主题 → 留理由／疑问 → 关闭再打开；可改条件、移除候选或删除主题 | N09、N12 |
| T6 直接找资源与入口 | 已有算力、文献、项目官网等明确需求 | 找到用途合适、限制清楚的入口 | 输入资源问题 → 看必要前提 → 原站；跳转即可结束，不强制创建主题 | N06—N08 |

以上是任务假设与设计方案，尚不是观察到的学生行为。导师探索常在一段时间内反复使用，资源查询可能一次结束；不据此设日活目标、自动提醒或强制返回任务。

## 3. 各任务如何操作

### 3.1 发现和补查：T1、T2

| 操作 | 系统应做什么 | 用户可继续什么 |
| --- | --- | --- |
| 输入问题、关键词或姓名并提交探索 | 先呈现已有资料；同时启动一次有范围的外部搜索和相关正文读取，保留本次问题与条件 | 立即看已有结果，也可等待、调整问题或停止外部查找 |
| 外部来源取得新信息 | 将具体陈述、原文依据和相关原因关联到人物、工作或途径；标明本次取得时间 | 看原文、打开详情、比较或主动保存 |
| 已知对象有缺口，选择补查 | 围绕对象和具体问题查找，例如“是否有面向外校本科生的短期研究说明” | 查看新增依据；没有答案时保留未知或原站入口 |
| 修改兴趣或参与目的 | 保留候选及私人记录，按新问题更新相关解释和比较视角；必要时发起新查找 | 可以回看旧结果和发起时的条件，不必重建主题 |

提交“探索”表示要求实际外部发现；只浏览已有对象或打开详情不必重新联网补查。可选参与途径、机构／地区条件可以清除；采用何种搜索服务、何时自动触发补查及具体接口由技术试验确定。不承诺全网穷尽。

每条结果最少回答：是谁／哪个团队、研究什么具体问题、哪些工作支持这种理解、为什么与本次问题相关、哪些参与途径已有依据。来源和与判断有关的时间、未知可就近查看；完整原文不必塞进列表。

已有资料和本次获取可以分辨；新来源补强一个已有候选也算发现成果，不要求每次新增导师。只有搜索摘要或链接、正文未取得时，不能说已读来源或已补齐事实。AI相关性解释与来源中的原陈述分开；AI解释不是招生确认。

**搜索途中改条件：**每次发现保留发起时的问题与条件。旧查找若继续返回，仍属于旧问题，不冒充按新条件筛过的结果。用户可停止旧查找、查看其已得信息或以新条件重查；旧查找不能覆盖主题的新条件，也不删除已保存候选。

**状态筛选：**兴趣探索保留招募未知者。“有本人／团队招募说明”只表示该途径有相应说明，长期欢迎不等于当前有名额；院系项目入口不能替代具名导师招募。主动要求“当前开放”时，只纳入有适用当前时期且明确支持开放的依据的途径，页面发布日期不能代替开放依据。其余条目区分已关闭／截止、当前状态未知；个人资格另按已知条件说明，不把未知当不符合。

#### 外部结果如何整理

每次补查围绕当前问题保留输入与本次范围，并把实际读到的相关信息整理成可查看的候选或依据：人物／团队、研究工作、参与途径与资源分别关联；说明与问题的联系、来源页面和原文依据。来源发布时间、适用时期与本次取得／检查时间分开；未知、历史状态、原文陈述与AI解释分别表达。只取得搜索摘要或链接而未读到相关正文时，保留为待查线索，不当作已确认事实。

结果不强制进入私人主题。用户可以直接查看、比较或结束，也可把候选及所用依据保存到选定主题；补查得到的公共资料按同一事实与来源结构复用，私人问题与理由不因此成为公共资料。

#### 查找中止与运行上限

用户能中止正在进行的外部查找，保留原问题、已取得的信息、比较选择和已存主题记录。中止后停止后续搜索、读取、AI整理和自动重试，按工具能力尝试取消在途请求；迟到返回不继续自动写入该次已中止任务的候选或私人记录。已经发出的请求可能仍被外部服务处理，中止不等于撤回数据，涉及个人内容时按下文发送状态说明。

单次查找须有运行时间、来源／调用数量及适用费用额度的上限，具体阈值与可控制范围在技术试验中确定。达到上限后停止自动扩查与重试，说明停止原因及已完成范围，让用户继续使用部分结果、调整问题、主动发起后续查找或结束。不会因取消或达到上限清空已有资料，也不把部分完成显示成全范围完成；不要求用户每次先填写一份预算表。

已有样稿的默认顺序只是编辑顺序，不表示推荐或质量，也不是外部发现的覆盖上限。已有资料无匹配、外部无结果与搜索／正文读取失败分别说明，不写“没有这样的导师”。

### 3.2 理解和比较：T2、T3

人物详情先回答研究内容，再按需查看参与途径、经历与支持。研究作品中的具体问题优于只展示“人工智能”等标签，但一项合作不能代表全部方向，也不能确定日常指导人。

| 比较问题 | 展示依据 | 避免误判 |
| --- | --- | --- |
| 想研究什么 | 具体问题、方法简述、代表工作及人物关联 | 论文共同作者不自动等于课题组负责人；解释不变成能力门槛 |
| 怎样参与 | 本科科研、短访、硕博项目各自的关系、条件、时期、原入口 | 本校项目不能默认适用外校学生；机构制度不代表本人接收 |
| 哪些条件影响当前路径 | 硬要求、优先项、建议及适用对象 | “优先”不改写成必须；个人条件未知不判符合或不符合 |
| 介绍之外知道什么 | 可用经历、关系／去向记录、交流入口与背景 | 校友去向不等于培养质量；缺少经历不代表负面 |
| 还需要确认什么 | 未知条件、来源冲突和私人疑问 | 不用AI补出确定答案或把缺信息计为低分 |

本轮建议不用综合适配分，以具体差异和依据支持判断。比较选择是临时阅读操作，收藏是持久记录，二者分开。先用两名真实候选验证可读性，不是永久人数上限；移除比较项不移除收藏，剩一人仍能阅读，零人时给出返回结果入口。

可以只比较研究内容，也可切换到本科科研、短访或研究生视角。切换视角保留人物及原记录；“某一途径暂不适用”不能被写成“这位导师不适合你”。多个视角可共存，私人理由按主题保存。

### 3.3 进一步了解与准备：T4

“介绍之外的信息”不设为必读阶段。已有材料可按以下名称呈现：

- 本人／团队说明：展示其承诺或介绍及来源。
- 参与者经历：保留叙述者与团队的关系、时期、原文和能支持的问题。
- 关系／去向记录：只说明关系和公开去向，不改写为指导品质。
- 交流入口：只使用公开用于相关交流或经同意展示的方式，说明知情者角色、与导师关系及时间背景；不保证回复或代表导师认可。

公开作者邮箱不能自动当作校友咨询入口；没有合适联系入口时保留具体疑问，不编造联系人，也不要求学生提交第三方联系方式。是否联系、何时联系以及问什么由用户决定，系统不发送消息。

例如“想知道本科生通常由谁指导”可以成为待问项；不是默认要求用户查完所有培养问题。准备帮助只解释与当前研究／途径有关的少数重点、原因及可选路线。算力不足时接到资源用途、权限和原入口；可申请不等于已经可用。跳转、暂缓和换方法都允许结束，不生成能力差距榜或课程任务链。

### 3.4 保存和继续：T5

建议返回入口名为“我的探索”。每个主题以当前问题为中心，例如“暑期尝试AI系统研究”“长期了解软件方向导师”；用户可自由命名，不强制选类别或填写全部偏好。

| 操作 | 最少保留什么 | 行为约束 |
| --- | --- | --- |
| 第一次保存候选或依据 | 选择已有主题或新建主题，记录对象及相关依据；名称可从当前问题建议后修改 | 浏览不用先建主题；新发现不自动收藏，新主题不自动代表申请计划 |
| 保存理由／待问项 | 用户选定或输入的理由、疑问，与主题内候选关联 | AI可以建议草稿，未经用户保存不能当作其真实偏好 |
| 返回主题 | 当前问题与条件、候选、选定依据、理由、疑问，以及关联的查找背景 | 无需重读整段聊天才能恢复；不把“继续申请”作为默认行动 |
| 修改问题／偏好 | 保留原候选与私人文字，按新条件重新解释或查找 | 不静默改写原理由；对旧依据保留原背景 |
| 移除候选／删除主题 | 只处理所选主题内的私人记录 | 不删除公共人物和另一主题的候选／理由；完整删除主题需可理解的明确操作 |
| 保存失败或内容未保存 | 明确显示未成功，保留当前编辑内容并允许重试 | 不显示虚假“已保存”；有未保存修改时，离开前允许保存、放弃或返回 |

同一候选可加入多个主题，例如同一AI系统导师在“暑研”中是短期尝试，在“读博”中是长期方向待定；私人理由、待问项及相关性解释分别保留。公共作品和来源可以复用，但不能把某个学生“不喜欢AI for Math”写成公共导师标签。

私人理由和待问项归属于“某个主题中的某个候选记录”，不能存入多人共用的公共人物资料。修改主题A中的理由、取消候选或删除主题A，仅影响A的私人记录；主题B的记录和公共资料仍保留。切换主题时使用该主题的偏好和私人记录，公共检索／合并不会带入其他主题的理由。公共事实发生变化时说明变化，不替用户重新写理由；用户可以按新依据自行修改。

持久保存须在明确支持的设备／浏览器范围内实现；仅页面内存不足以满足关闭再打开。首版不要求账号、跨设备同步或完整聊天历史。具体存储、删除行为和对外AI传输范围在技术设计时明确；任何新建／修改／删除界面都应与真实保存行为一致。

### 3.5 资源与入口直达：T6

输入用途或资源名称后，结果只保留用途、关键适用前提、费用／权限性质、来源时间和原入口。资源能与某个主题或准备问题关联，也可完全独立使用。

入口已找到就可以离开。外站要求登录或申请时说明它是外站步骤，不代办、不索取第三方账号密码，不把尚未获批写成可使用。不为显得内容丰富而展开逐章节教学或通用准备清单。

### 3.6 个人内容与外部AI：T1—T5

以下是已采纳的集成要求。当前应用没有外部AI调用或个人内容发送界面；固定来源解释不等于已实现这些行为。

个人问题、偏好、私人理由、笔记和待问事项，仅在用户明确选择后才能发送给外部AI。发送前能看见本次选中的具体内容／片段、接收服务和用途；用户可以取消选择或不发送，发送操作本身可确认这次选择，不要求重复确认。保存、浏览、切换主题和曾经发送某一条内容都不代表其他私人内容也可发送。

公开资料的AI整理与个人内容发送分开：仅选择主题A的一条理由时，请求只能附带这条选定理由及任务所需公共依据，不能自动携带A的其他笔记、主题B的内容或整份探索记录。关键词展开、摘要、比较、重试和历史上下文均遵守该边界，未选择内容不能经改写或摘要绕过选择；由个人内容生成的摘要仍按私人内容处理。AI输出涉及选定个人内容时保存在相应私人主题，不回填公共资料。取消选择后不再用于后续请求，也不自动续用包含该内容的外部会话上下文；本地删除不宣称外部服务已同步删除，外部保留与删除条件在选定服务后明确。未选中个人内容时仍可使用公共资料发现、浏览、比较、保存与原站入口。完整边界见[隐私说明](privacy.md)。

#### 个人内容的发送状态

选择内容与实际发送分别显示。只有能够确认请求尚未发出时才显示“尚未发送”；已发出则显示“已发送，等待结果”，收到响应后显示结果或返回的错误。发生超时、断连或取消而无法确认送达时，明确显示“发送状态未确认，可能已发送”，不据此承诺内容未离开本产品或已被撤回。

用户中止任务或取消内容选择，会阻止后续请求附带该内容，并按工具能力停止等待；已发出的内容仍按接收服务的实际规则处理。主动重试前能查看这次仍选中的内容、接收服务和前次状态，重试不自动扩大个人内容范围，也不因未收到结果而无限重发。

## 4. 信息关系：共用资料与私人判断分开

这是概念结构，不指定数据库、API或模型供应商。最重要的关系是：

**人物／团队 → 研究工作与参与途径 → 有来源的具体陈述；探索主题 → 主题内候选 → 选定依据、私人理由和疑问。一次查找关联发起条件及取得的信息。**

| 对象 | 最少内容 | 关系与边界 |
| --- | --- | --- |
| 人物／团队 | 稳定标识、姓名、机构、身份依据 | 同名不自动合并；与多项研究及途径关联，换机构需保留时期 |
| 研究工作 | 具体问题、方法简述、作品入口、人物关联依据 | 原陈述与编辑／AI解释分开；不代表全部方向 |
| 参与途径 | 类型、人物／机构关系、适用身份、时期、条件、状态、原入口 | 本人招募、院系入口、制度上的待核路径分开；一人可以有多个途径 |
| 陈述与来源 | 所述事实、适用对象、要求性质、原出处、发布时间／适用期、取得时间、核对状态 | 一事实可有多来源；来源可读、关系成立、当前招募和个人资格分别判断 |
| 经历／交流入口 | 角色、关系、时期、原文、交流用途或展示同意依据 | 转述不算独立佐证；没有材料时留空，不用AI填补 |
| 资源／办理入口 | 用途、关键前提、费用／权限性质、链接与状态 | 可独立查询，也可关联途径或准备需要 |
| 发现过程 | 发起问题和条件、搜索／读取范围、取得来源与具体信息、时间、结果／失败项、运行／中止／限额状态 | 区分旧资料和本次获取；迟到结果仍绑定原问题且不自动写入已中止任务；保留部分结果；不要求保存完整原网页和全部聊天 |
| 探索主题 | 名称、当前问题、可选偏好、关联发现过程 | 私人上下文，多个主题独立；主题不要求绑定单一途径 |
| 主题内候选记录 | 引用公共对象、选定作品／途径／依据及时期、私人理由、待问项 | 同一对象在两个主题中是两个记录；修改／删除一份不影响另一份或公共对象；来源失效不删除私人理由 |
| 一次个人内容发送选择 | 本次选定内容／片段、接收服务、用途与所属主题、已知发送／返回状态 | 仅组装明确选择的个人内容；取消后不用于后续请求；无法确认送达时保留未知，不要求永久保留发送副本 |

查找可在尚未保存的临时上下文中进行；首次保存时把所选候选、依据和必要问题背景纳入主题，不强制保留未选发现。重复来源保留关联，不重复增加“独立佐证”数量。

新外部信息先保留出处和可支持的陈述；涉及当前名额、个人资格、身份关联等关键结论按核对状态展示，团队处理关键错误、冲突和例外。无须先建立完整运营后台。公共资料修正可以影响事实展示，但不自动改变私人理由；正在使用的旧依据仍可辨认其时间和状态，不能被悄悄换成新结论。

#### 与已有资料如何合并

合并先判断是否为同一人物／团队及同一事实、作品或参与途径，再决定复用、补充或保留待核。仅姓名相同不足以合并；机构、身份、作品和原文关系等依据不足时保持分开。demo可用文件流程处理待核项，不要求先建维护后台。

| 本次结果 | 整理与合并规则 |
| --- | --- |
| 再次读到同一来源中的相同信息 | 复用已有候选及依据，成功读取后记录本次检查时间；不重复新增候选或把它称为新人物 |
| 已有人物的新作品、新途径或补充条件 | 关联到对应人物，保留各自来源、适用对象与时期；不同途径保持独立 |
| 同一事项有多份来源 | 保留来源关系，补充能够支持的具体陈述；转载／转述不自动算独立佐证 |
| 条件、身份或招募状态互相冲突 | 保留各版本及其时间、对象和来源，标出待确认；不只因本次抓取更晚就覆盖旧值 |
| 新来源给出更正或当前状态 | 可更新有依据的公共事实并保留必要旧依据；已保存主题中的私人理由及所引用依据不被静默改写 |
| 身份或关联仍不明确 | 保留独立线索及待核原因，未经确认不去重、不强行关联 |

#### 错误合并如何修正

发现同名人物或不同参与途径被误合并时，维护者能通过demo文件流程拆开公共记录，把各来源、作品、条件与途径关联回正确对象，保留必要的更正依据。修正不删除私人理由、待问项或旧引用，也不把一个主题的理由复制到另一主题。

原有主题记录的对象能够确认时修复其关联并让用户看见更正；无法判断一条私人记录原本指向哪位人物／哪条途径时，保留记录及原依据，标为关联待确认，由用户选择关联对象。不会自动把私人理由分配给所有拆出的对象，或擅自替用户改写理由。具体存储标识与修复方式留技术设计，不要求新增管理后台或完整版本系统。

修复公共关联不要求维护者查看私人理由原文；需要用户判断的关联在其私人主题中确认，不因纠错新增对私人笔记的访问权限。

## 5. 页面组织建议

导航建议为“探索”“资源与入口”“我的探索”。对象详情与比较从结果或主题进入，属于同一任务中的视图，不是独立必走阶段。具体采用页面、侧栏或对话框，留到Primer交互稿验证。

| 位置 | 首要内容与动作 |
| --- | --- |
| 探索 | 问题输入、可选条件、已有／新取得结果、相关依据，查看／比较／保存／补查 |
| 人物详情 | 具体研究、参与途径、按需经历与支持；原站、返回、保存一直可达 |
| 比较 | 当前比较问题、候选及有依据的差异；可改视角、移除、回详情 |
| 我的探索 | 各主题的问题与候选；继续、修改、移除；进入主题即可恢复理由和疑问 |
| 资源与入口 | 用途查询、关键限制、原入口；不强制经过人物页面 |

查找状态仅展示有实际依据的“正在搜索”“正在读取”“正在整理”及结果／失败项，不编造完成百分比或等待时间。已得结果可以先阅读；执行方式是否支持逐步返回在技术试验中核对，不以动画冒充进展。

窄屏比较按同一个问题连续展示各候选并保留姓名，避免必须反复横向寻找。检查键盘、焦点、返回和链接辨识。所有UI遵循[Primer规范](ui-system.md)；现有HTML原型只复用内容／操作经验，不复用其样式。本文不新增视觉规则或手写CSS例外。

## 6. 异常时仍能完成什么

| 情况 | 对用户的解释及恢复 | 需要保留的结果 |
| --- | --- | --- |
| 已有资料无匹配／外部无相关结果 | 分别说明检索范围，可改词、清条件、看原站；不说不存在这样的导师 | 当前问题与已保存候选 |
| 来源取得部分成功 | 展示实际读到的内容和未完成部分，可主动重试、改查其他来源或打开原站；未读取来源仍是待查线索 | 原问题、成功来源与依据、比较选择和已存记录保留，不因一项失败清空整轮；未读条件仍未知 |
| 外部访问失败／要求外站登录 | 区分搜索失败与正文读取失败，说明失败位置，可继续已有资料、改查来源、主动重试或去原站 | 旧资料标明原取得时间；未读取线索和失败不算本次发现通过；原问题、成功信息、比较选择和已存记录保留 |
| AI整理或解释失败 | 保留可读来源、已确认关联和入口；仅检索摘要时不称正文已读 | 不用生成的占位结论填空；原文可继续查 |
| 招募过时／来源失效 | 标明时间或访问状态，当前开放仍未知 | 历史价值和私人理由保留 |
| 来源冲突 | 同时保留适用对象、时期、各自依据及待确认处 | 不覆盖为单一确定答案 |
| 经历／合适联系人不足 | 说明现在能回答什么，可留一个具体问题或结束 | 不生成黑红榜、假经历或未经许可联系方式 |
| 资源不适用／用户不想继续 | 可换入口、换路径或停止 | 不自动追加准备任务或催促 |
| 保存失败／删除操作 | 给出实际结果与重试路径；删除明确作用范围 | 不虚报保存；不误删其他主题或公共资料 |
| 用户中止／达到运行上限 | 说明停止原因及已完成范围，继续使用部分结果、调整问题或主动发起后续查找 | 原问题、已得信息、比较选择和已存记录保留；停止后续调用／自动重试，尝试取消在途请求，迟到结果不自动写入 |
| 公共对象或途径误合并 | 拆分修复公共关联；原私人关联不明时由用户确认 | 私人理由、待问项和原引用保留，不复制给所有拆出的对象；纠错不新增私人原文访问权限 |
| 个人内容发送超时／断连／中止 | 无法确认送达时显示可能已发送，不宣称撤回；主动重试前展示当前选择及前次状态 | 后续请求不带已取消内容，不扩大选择或无限重发；本地记录保留，外部处理按实际服务规则 |

主动重试按第4节合并规则去重，不重复新增候选或静默改写私人理由。至少一次真实外部发现仍须成功读取相关正文并用于整理；失败及模拟故障不替代该项验收。

这些分支从最初设计保留，不等正常流程完成后才补。实现检查可模拟异常，但演示记录须区分模拟、真实失败与真实内容变化。

### 8.5 从比较中的疑问补查并回到比较

比较中的“补查”按候选公开姓名、机构和当前参与视角预填可编辑检索词。可以搜索，也可以选择已收录的官网页面并点击“读取原站正文”；选择页面本身不会请求。直读仅访问所提交的一个范围内公开HTML页面及通过相同校验的重定向，不经搜索索引，失败不换成目录或演示数据。小红书等浏览器来源仍通过其原有入口阅读，不加入此静态HTML读取菜单。

实际读取后显示正文、来源、取得时间和本次范围。直读没有关键词匹配解释，也不自动判断属于哪位导师或回答了哪个疑问。用户核对后明确确认关联，补充依据才保存到当前主题；不会改写固定比较摘要、清除待问项或自动标记当前可申请。与同一主题的候选合并，重复保存同一份结果不会增加候选或来源；另一次取得的快照可以保留其时间差异。

2026-10-08的走查已验证公开查找和保存机制，但所读通用页面不能证明补查到了该导师的关键信息。10月12日从江祖铭比较发起官网直读，实际取得本人主页的系统／安全／数据库方向、博士与RA招募说明及近期工作正文；当前名额和详细RA条件仍未知。重复保存、返回比较、刷新恢复和双主题隔离均通过开发者走查：保存依据保留原私人记录及页面内未保存草稿，刷新只恢复主动保存的内容。390px页面无横向溢出，菜单后可用Tab到达读取按钮。

### 8.6 主题条件编辑与可中止、有上限的发现（2026-10-22）

沿用G1—G3及已有浏览器主题存储，不新增模型、账号或采集平台。主题名称、当前问题与可选偏好现在可显式编辑保存；失败保留草稿，离开未保存弹窗时提供保存／放弃／继续，刷新有未保存提醒。修改条件不改写候选、依据、私人理由／待问项和其他主题，也不自动组装公开查询。

同一发现接口新增逐行累计返回正文与完成范围的路径。浏览器收到每份正文即可阅读或主动保存；中止后保留已收到内容，不自动重试。修改查询后主动重查、切换主题／候选／场景或离开视图时，旧请求先失效再取消；迟到数据不覆盖新结果，不自动存入另一主题。

当前试验上限：服务端整轮30秒，最多5个来源、6次读取（含检索），每次14秒和1 MB；每次最多4次HTTP尝试，计入可能的地址解析备用HTTP请求，整轮最多48次外部HTTP请求。浏览器连同传输最多等待35秒。来源超量或时间到达会说明停止原因，已到达的部分正文保留；断流但缺少结束标记不能当完整成功。未调用收费模型或收费搜索API，原有来源限制与安全检查继续适用。停止不能撤回已发出的公开请求。

开发者浏览器走查使用两个新建合成主题验证编辑／继续编辑／保存／刷新、双主题条件隔离，以及已有候选、来源和合成私人记录在改条件后保留。公开关键词查找本次遇验证页并转入有限目录，失败／无匹配保持可见；官网直读另取得江祖铭主页正文，重复保存未增加重复候选或来源；实际请求中可中止并显示收到范围。390px iframe视口检查了编辑弹窗和控件，没有将这次界面检查称为完整无障碍验证。

另外用生产客户端控制器对实际官网流式请求，在收到第一条正文而结束标记尚未到达时立即中止，确认保留该正文且状态仍为中止；未将其伪报为完整结束。旧请求迟到、等待上限与失败继续另以受控传输回归；Rust检查中止／超时丢弃在途任务、保留已完成正文及释放并发名额。全套第7节G5走查、误合并修正、准备／知情者／资源入口以及外部AI输入和发送状态仍未完成；本节是开发者切片，不是学生收益或完整demo验收。

### 8.9 误合并修正：公开拆分与私人记录关联（2026-10-27）
