# Campus Lumen：大学生机会探索与决策支持 — 需求分析 v1.0

Last updated: 2026-10-29

版本：v1.0。状态：依据发起者已确认决议形成的需求基线，可交接评审并用于后续设计。本文是当前需求的主阅读入口；同伴评审意见另行记录。产品尚未完成实现和实际用户效果验证。

## 摘要

Campus Lumen 帮助大学生发现分散的机会与支持，理解实际内容、比较适配性，并自主决定是否继续了解、如何准备以及从哪里取得帮助。初期服务科大学生个人，信息范围跨院校、研究所、地区和学科。

当前中期交付是一套可操作的机会探索 demo：所有机会类型在前端共用“探索 → 发现 → 处理”流程。选导师是内容最深的示例，用户可复用已有资料并实际读取外部来源、比较候选、查看进一步了解和资源入口，并在多个探索会话中保留自己的判断；其他类型使用已有整理入口验证流程复用，不据此声称同等资料深度。

整体需求研究覆盖科研、升学、实习、竞赛、交流、活动通知和学习支持。选导师是第一个深入场景，不能代替全产品用户研究。先展示信息汇集与组织的帮助，再决定是否投入真实模型和长期维护。

## 1. 问题背景与证据

高校和外部机构已提供大量机会与资源，信息按院系、机构、项目和发布渠道组织。学生则从自己的兴趣、目的、时间和条件出发，需要跨来源发现选项、理解差异，并了解介绍之外的实际参与情况。问题不以“学校没有平台”为前提，而在于已有信息怎样转化为个人可使用的判断依据。

| 已有证据 | 支持的需求判断 | 采用范围 |
| --- | --- | --- |
| 科大软件学院就业提醒报告整理20余家单位、300余岗位，并通过群转发 [S1] | 本地已有丰富供给与人工聚合，多渠道查找是实际情境 | 规模为校方自述，不推算遗漏率或需求人数 |
| RSTAR官方上线通知介绍导师、项目和资源服务 [S2] | 校内已有重要替代，应复用并比较其价值 | 已读通知，未验证登录内能力及跨校覆盖 |
| 2010年美国25校8,353份自愿问卷中，41%报告相关性筛选困难，18%报告选择信息源困难 [S3] | 找到信息与判断相关性是不同需要 | 回应率7.4%，支持共性问题，不作为当下科大比例 |
| 国内18名成功求职毕业生访谈研究 [S4] | 线上、线下和人际渠道具有互补价值 | 既有研究仅读摘要，有样本选择限制 |
| 40名早期物理博士生访谈及导师选择研究，见[文献与案例记录](../constraints/mentor-workflow-evidence.md) | 方向探索和指导关系适配值得分别考虑 | 质性机制可参考，不能移植博士制度或推断具名导师品质 |
| 发起者对跨机构导师探索、经历线索、准备、资源及多主题接续的明确诉求 | 形成首个真实案例和产品取舍依据 | 个人诉求与文献、案例并用，不代表全校发生率 |

证据按人群、任务和情境可比性采用。相近学生群体研究可以支持科大学生的共性需要；学校声望或样本量本身不保证代表性。具体制度、资格和当前开放状态仍以对应来源为准。

**需求结论：**已有材料足以支持发现、理解比较、实际情况考察及按需帮助这些需求，允许进入产品设计。是否更省时、更好用留到具体任务验证，无需重复组织一轮本地问卷才采用已有结论。

## 2. 产品对象与用户任务

### 2.1 整体用户与任务

初期直接使用者是科大学生个人。按正在处理的问题组织能力，允许目标尚不明确、目的重叠或改变；年级和专业只在影响资格或理解时作为上下文。

| 使用状态 | 希望得到的结果 | 可出现的场景 |
| --- | --- | --- |
| 探索可能性 | 认识此前不了解的方向、事情或参与形式 | 科研方向、职业、竞赛、文化体验、学习路径 |
| 寻找与比较 | 找到相关选项，理解差别并形成自己的理由 | 导师、实习、交流项目、课程与资源 |
| 考察实际情况 | 结合经历、记录或知情者进一步了解适配性 | 指导方式、实习带教、比赛投入、活动组织、资源使用体验 |
| 判断如何开始 | 了解必要基础、准备重点和可选起点 | 科研、申请、比赛、学习或实践 |
| 直接找入口 | 获得适用入口及最少必要说明 | 算力、文献、活动通知、报名、认定规则 |
| 接续探索 | 分别保留不同目标的候选、依据和判断 | 跨次比较、调整方向、暂存待问问题 |

动机可以是兴趣、共同参与、正式认定、学习、研究或就业，并可同时存在。例如好玩与综测加分可以兼得；认定须按学校／院系、年度及适用规则判断，奖项、学分和综测分别表达。

### 2.2 首个交付：选导师

用户可探索本科进组、短期科研／访问或研究生导师／项目。同一导师可有多种参与途径；研究相关性、招收状态和个人资格分别判断。

- 兴趣模糊时，通过具体研究问题与作品认识方向。
- 已有目标时，寻找候选，比较研究内容、参与途径、条件和未知。
- 想深入了解时，查阅经历依据或找到合适知情者的交流入口。
- 决定继续时，按需看准备重点、资源或原平台入口；也可保存、换方向或停止。

首个真实案例来自人工智能与数据科学学院学生（沿用发起者简称 AIDS），偏研究、AI与软件，较少考虑AI4S和AI for Math。这些是案例偏好，不是全产品限制。导师探索可能集中在一段时间反复发生，实际频率尚未测量；无需设计连续使用目标。

### 2.3 内容提供者与受影响者

demo资料以自动化为主整理，团队承担关键核对、异常处理和改错，可使用文件流程。导师、项目方和被引用参与者是信息对象与受影响者，可就具体陈述提出更正或异议。个人笔记保持私有，公开内容的纠错不要求公开用户判断。

初期维护投入有限。持续服务的负责人、更新周期及响应承诺在决定继续投入时安排；不为demo先建设机构端或维护后台。

## 3. 现有解决方式与产品增量

| 现有办法 | 已有价值 | 本产品承担的补充 |
| --- | --- | --- |
| 官网、院系、课题组和项目页面 | 原始研究、条件、状态和办理入口 | 跨来源发现，关联人物、工作与具体参与途径 |
| RSTAR [S2] | 本校科研导师、项目与资源服务 | 检验跨机构发现和个人比较的帮助；不推断其未验证功能缺失 |
| 搜索＋通用AI＋笔记／表格 | 灵活查找、解释、比较和保存 | 将重复调研过程做成可接续的工具，保持来源与判断关联 |
| 熟人、群聊、公众号和小红书 | 信息传播、情境和参与经历 | 连接可用线索与知情者，帮助继续了解，保留原渠道价值 |
| Stanford SOLO、Handshake [S5–S6] | 机会聚合、筛选及专业平台分工 | 借鉴统一发现入口与外部办理，不以列表或提醒宣称独创 |
| Zotero、Notion、Perplexity等资料工具 | 按集合／项目组织资料、笔记与对话 | 复用多主题组织模式，同时把研究、参与条件和私人理由关联起来 |

多主题案例及官方文档见[工作流调研](../constraints/mentor-workflow-evidence.md)。信息不必独家，集中原本分散且相关的信息本身可以有帮助；实际收益取决于相关性、可理解性与使用便利，不能仅用条目数衡量。

本产品选择“相关信息汇集＋按需理解比较＋接续探索”的组合。简单入口查询可以直接结束，深任务逐步展开；不把所有人引导进同一条长流程。

## 4. 具体问题与未满足需求

沿用P编号表达问题，N编号表达使用要求。下列原因是结合案例与研究形成的分析，尚非各问题发生率数据。

| 问题 | 障碍／原因 | 用户需要的结果 | 对应要求 |
| --- | --- | --- | --- |
| P01 难发现相关选项 | 信息按提供者分散，个人按目标寻找 | 尽可能找到可获取的相关信息和进一步了解入口 | N01–N03、N08 |
| P02 难理解比较 | 粗方向标签、参与方式与条件层次不同 | 看懂实际工作及影响选择的差异 | N03–N05 |
| P03 不知道如何开始 | 缺少基础到具体任务的衔接说明 | 知道准备重点、原因和可选起点 | N06 |
| P04 资源不适配 | 权限、费用、时间或设备前提不符合，例如算力注册条件 [S8] | 找到适用支持或替代，也能判断暂不使用 | N07–N08 |
| P05 难接续不同探索 | 候选、判断与来源分散，不同目标混在一起 | 分别保留目标、候选和理由，回来继续 | N09 |
| P06 不清楚已有要求及入口 | 活动／项目介绍与适用制度分开 [S9] | 看懂适用规则并到达正确入口 | N08；自动进度N13后置 |
| P07 自述不足以了解实际情况 | 宣传或介绍不能回答日常体验和承诺兑现 | 结合经历、记录、知情者及未知自主判断 | N11 |

P07是跨场景共性需要，考察内容随任务变化；导师场景的考察维度可参考实践指南 [S7]。教师的研究产出可说明研究工作，不能直接说明指导质量；自述、事实记录、参与者经历和私人判断应分别表达。

P05已作为发起者确认的产品需要采用，但真实返回收益仍待观察。保存不推出推送、进度追踪或长期高频使用。产品能改善信息获取与判断，无法代替录取、名额、资源审批或消除时间和经费限制。

## 5. 产品价值与使用原则

**定位：大学生机会探索与决策支持。**发现、理解与比较是核心；准备指导服务当前选择，资源连接提供可用支持。用户通过已有网站难以直接组织的信息，在本产品内形成可理解、可比较、可接续的探索结果。

- **个人独立可用：**不依赖社区活跃；未来共同维护是可选扩展，没有预设阶段。
- **自主选择：**浏览和保存不代表承诺参与；暂停、拒绝或只看入口都可以完成任务。
- **帮助按需：**提供准备重点、理由和可选路径，避免统一成长任务、欠缺排行榜和默认催促。
- **来源服务判断：**保留来源与时间；历史项目也可帮助认识方向，当前能否申请另行判断。
- **保持渠道价值：**办理回原平台，进一步了解可连接知情者；学校已有资源也须判断个人适用性。
- **保留个人判断：**不同主题可形成不同理由，不生成导师人格总分或公开黑红榜。

价值主张是减少寻找与组织信息的困难，具体节时、录取收益或焦虑变化尚未测量。初期先展示可观察的帮助，再决定长期投入。

## 6. 范围与优先级

### 6.1 中期 demo 承担什么

| 层次 | 已确定范围 | 交付边界 |
| --- | --- | --- |
| 统一流程 | 所有机会类型共用“探索 → 发现 → 处理” | 选导师内容最深；其他类型沿用现有整理入口，不新增调研采集 |
| 深入示例 | 选导师中的发现、理解与比较 | 校内外统一处理；包括人物、研究与参与途径的关联 |
| 必需发现能力 | 复用已有资料，并实际进行外部搜索、读取与整理 | 只搜索预存数据不足以满足 demo；不保证每次发现新人物 |
| 探索接续 | 多个会话保存候选、来源、私人理由与待问项 | 允许多次访问，会话间偏好分开；浏览可先于会话创建 |
| 按需支持 | 准备重点、资源与原入口 | 可独立查找或跳过，支持可自然结束的轻任务 |
| AI 整理 | 明确标注的本地模拟服务 | 验证逐条选择个人内容与发送状态；真实模型接入后置 |
| 有条件内容 | 实际经历、相关记录、知情者交流入口 | 根据来源可得性提供；不足时明确缺口和进一步了解路径 |

2026-10-15 用户纠正了“其他机会类型不属于首版”的旧口径；2026-10-29 进一步确认统一前端流程。现有资料的覆盖和深度仍不均衡，流程开放不等于承诺全量或同步调研。

### 6.2 本次不承担什么

本次不为其他机会类型新增调研采集，也不承诺与导师场景相同的内容深度。通知推送、自动个人进度、跨设备同步、完整聊天系统和复杂后台不列 demo 必需。社区、公开评价、代办申请、自动联系导师和知识教学／练习测评均不在当前范围。用户决定联系导师时，联系前可了解的内容和待问事项属于 N06／N11 的可选帮助；代写联系邮件、管理多位导师的联系进度或回复冲突不在当前范围。

长期值守、全量实时更新及持续覆盖承诺后置。若后续有价值且值得继续投入，再决定扩大来源、共同维护或更多场景；不因已有代码或研究材料而自动新增任务。

## 7. 功能与使用要求

### 7.1 需求追溯

| 编号 | 已采用行为 | 可检查结果 |
| --- | --- | --- |
| N01 | 从模糊兴趣、明确对象或资源需求进入，条件可调整 | 不用完整画像即可开始；改条件不丢已保存候选 |
| N02 | 检索已有资料并按问题搜索、读取和整理外部信息 | 来源、相关原因与覆盖范围可见；重复对象复用、补充事实关联、冲突保留待核；失败、中止或达到运行上限时继续使用成功信息和已有资料 |
| N03 | 关联人物、研究工作、参与途径与资源 | 同一人物不同途径分开；可返回原文查看依据 |
| N04 | 解释实际任务、资格、优先项及建议 | 不把“优先”变成硬门槛，不把研究方向当当前招生；外校／海外途径的语言考试、签证或身份前提按途径和来源单独标出，院系要求不泛化为全校门槛 |
| N05 | 按当前问题比较候选 | 关键差异与未知可读；缺资料不当零分或负面评价 |
| N06 | 按需提供准备重点与理由 | 已有基础者能跳过；不要求固定练习或作品产出 |
| N07 | 查找适用资源，可独立进入 | 用途、权限、费用性质和入口清楚；可申请不等于获批 |
| N08 | 区分适用时期、状态与官方入口 | 旧招生作为历史参考，未知不被当成当前开放 |
| N09 | 按探索主题保存候选、依据、私人理由及待问项 | 重开后恢复约定范围的数据；理由归属具体主题记录，切换／修改／删除一主题不混入或改写其他主题及公共资料 |
| N11 | 呈现经历依据并连接合适知情者 | 保留关系、角色、时期和来源；联系入口须公开用于相关交流或经同意展示，不保证回复 |
| N12 | 整理、关联、核对和改错 | 已知错误及误合并可修正，保留私人记录与原依据；人工与自动化分工如实说明，无需先建后台 |

N10为可选通知、N13为已有要求的自动进度，沿用编号但不进入当前交付。完整编号和分析契约见[需求基线](requirements.md)。

### 7.2 工作流与信息关系

深入探索可按“输入问题 → 复用资料 → 外部补查 → 理解比较 → 按需了解经历／准备／资源 → 保存或结束”进行。用户可跳过、回退或从中间进入；轻任务找到适用入口即可结束。

公共资料与个人探索分开：公共部分组织人物／团队、具体研究、参与途径、条件、来源和时间；个人主题保留当前问题、偏好、候选及判断。同一导师可关联多个参与途径，也可加入多个个人主题。公共事实变化不应静默覆盖用户原有理由。

本次取得的信息按人物／团队、研究工作、参与途径和资源整理，保留具体原文依据、与问题的联系、来源发布时间、适用时期及取得／检查时间。已有对象复用，新作品、途径或条件分别补充；仅同名不足以合并，重复读取不重复新增候选。冲突保留各来源和适用情境，身份或关联不明保留待核，不以本次抓取较晚为由直接覆盖。主题中的私人理由与公共事实分开保存，公共资料合并／更正不自动改写私人理由或原引用依据。具体操作与检查见[任务设计](advisor-task-design.md)。

误合并的人物或参与途径可以拆开并修复公共关联，demo可使用文件流程。保留主题中的私人理由、待问项及原引用；无法确认原关联时由用户选择正确对象，不自动复制或分配私人理由给所有拆出对象。

实现方向已确定为调研方法、工具程序、已有资料和探索会话协同。程序处理固定操作；中期 AI 整理使用明确标注的本地模拟服务，验证选择发送与状态，不调用真实模型。真实模型、供应商、费用和保留条件在后续采用前另行设计。

### 7.3 异常与质量要求

| 情况 | 处理结果 |
| --- | --- |
| 无结果／外部访问失败 | 区分无结果、搜索失败和正文读取失败，说明本次范围及失败位置；保留原问题、成功信息、比较选择和已存记录，可调整条件、打开原站、改查其他来源、主动重试或结束；缓存注明原取得时间，重试按合并规则去重，未读取线索不冒充本次新发现 |
| 查找中止／达到上限 | 用户能中止任务；单次时间、来源／调用数量及适用费用额度有上限，阈值和可控范围在技术试验确定。保留部分结果及已存记录，说明停止原因和完成范围，停止后续调用及自动重试；尝试中止在途请求，迟到返回不继续自动写入已中止任务 |
| 资料过时／来源失效 | 保留历史价值与个人笔记，标明状态；不推断当前仍可参与 |
| 来源冲突／条件未知 | 显示来源、时期和适用对象，保留待确认，不擅自合并为确定答案 |
| 经历缺失 | 展示已有信息和可用交流路径；不以AI编造或通用清单冒充真实经历 |
| 资源不可用／用户不想参与 | 支持换路径、暂缓或结束，不自动追加准备任务 |
| AI解释失败 | 已有来源、资料浏览及原入口仍可使用 |

个人目标和笔记默认私有；仅发送用户明确选择的个人内容给外部AI，发送前能查看本次内容／片段、接收服务和用途，可取消或不发送。选中一个主题的一条理由不允许自动附带其他笔记、其他主题或整份记录；保存、浏览和曾经发送不构成后续内容的自动发送许可。涉及个人内容的AI输出保持私有；取消选择后不用于后续请求。本地删除不宣称外部服务同步删除，真实数据进入前明确实际保存、删除及所选服务的保留条件。详见[隐私边界](privacy.md)。公开浏览不以校园认证为前提，外部平台可要求自身身份验证，本产品不索取第三方账号密码。

个人内容选择与发送状态分开：确认未发出、已发送等待结果、已返回及送达不明分别说明。超时、断连或取消不能证明内容未发出，无法确认时注明“可能已发送”；取消阻止后续发送，不宣称撤回先前请求。主动重试可查看当前选定内容及前次状态，不自动扩大范围或无限重发。

检查键盘操作、可见焦点、窄屏阅读、长文比较与链接辨识。前端遵循[既定UI规范](ui-system.md)，使用Primer体系；详细配色和组件限制留在该文档。性能目标结合实际样本与部署条件在技术设计时确定。

公开资料支持有限 demo 内容，但实际培养经历供给不均；目前尚无可交付的具名独立指导经历样本。2026-10-04 至 10-22 已接通公开查询／正文读取、Primer 页面、同源浏览器多会话保存、江祖铭／宋卓然有依据比较、官网补查回填、主题条件编辑、流式进度、中止与声明上限；静态资料库已含资源与规则入口。误合并修正机制已在整合分支实现，完整中期走查仍待执行。中期 AI 整理采用明确标注的模拟服务，真实模型未接入；准备重点和知情者内容仍取决于现有资料。具体执行记录见[任务设计第8节](advisor-task-design.md#84)和[项目进度](../project/progress.md)，本需求文件不代替运行或 CI 结果。

### 8.2 比赛demo验收

以下是待执行标准。走查记录输入问题、所用来源、操作结果、人工补位和失败项；用真实内容验证，作者走查与学生试用分别报告。

| 任务 | 达标结果 |
| --- | --- |
| 实际发现 | 面向一次输入实际搜索并读取至少一项相关外部来源正文，展示取得的具体信息、原文依据及其与输入问题的联系，并用于候选或依据整理；只返回搜索链接或无关页面不算完成，预存资料复用与本次获取可区分。访问失败记录为未完成该项，已有资料可继续演示其他能力 |
| 理解比较 | 至少两个真实对象能按当前问题比较具体研究、参与途径与关键差异；展示支持差异的来源，未证实条件保留未知，同一人物的不同途径不混淆 |
| 使用历史材料 | 历史资料帮助认识方向或候选，同时清楚区分当前开放与未知；关键条件可回到原文 |
| 进一步了解 | 有可用经历／记录或合适联系入口则呈现背景；材料不足时能辨认缺口和待问事项，不宣称已评价导师品质。呈现具名人物的经历或承诺兑现类陈述前，已确定来源使用方式和demo期间的更正处理人；按8.1现状，以缺口和待问事项呈现即可达标 |
| 准备与直达 | 需要帮助时能找到适用起点与资源入口；只查入口者无需完整画像、比较或准备 |
| 多主题接续 | 两个探索主题分别保存候选、依据与理由；在设计声明支持的设备／浏览器环境中关闭页面再打开后仍可恢复。同一候选加入多个主题时，各主题的私人理由分别保存，修改／删除一个主题记录不影响另一主题或公共资料；不要求跨设备同步 |
| 基本质量 | 重要事实有来源和时间，已知关键错误已修正；异常可理解、私人记录不公开，必要工程与可用性检查通过 |

把以下检查纳入上述实际发现、多主题和基本质量任务：重复读取同一来源不会新增重复候选，身份不明或冲突不被强行合并；一个来源失败后成功信息与私人记录仍可用，重试保持去重；公共资料更正不静默改写各主题理由。用合成私人内容检查外部AI实际请求：仅选择A的一条理由时只发送该个人内容及任务所需公共依据，不带其他笔记或B内容，取消后后续请求不再附带；无个人内容选择时仍可浏览、比较和保存。模拟故障与合成内容只验证处理规则，不替代至少一次真实外部正文读取。

同时检查部分结果取得后的中止及声明上限生效：保留结果与记录，后续调用／自动重试停止，迟到返回不继续自动写入。用合成对象修正一次误合并，检查公共关联恢复、私人理由和原引用保留、无法确认的关联交由用户选择；检查AI未发送、等待、返回及送达不明状态与实际证据一致，不将超时或取消显示为已撤回。按[任务设计](advisor-task-design.md)把真实发现、比较、双主题重开和这些异常检查串成一次待执行走查，模拟项仍分别注明。

demo通过表示这些行为可运行，不代表已证明普遍需求、实际节时或长期效果。演示材料中已知且会改变判断的错误应修正；未能完成的项如实记录，不能用预先整理结果替代一次成功的外部发现。
