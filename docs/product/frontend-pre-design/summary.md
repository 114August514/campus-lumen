# Summary：Campus Lumen 产品前端预设计——一页结论

Last updated: 2026-10-25

写给用户 · 2026-10-25 · Kimi 独立设计稿

## 产品到底有什么

Campus Lumen 是大学生个人的**机会探索与决策支持**工具，由五组能力组成：**发现**（复用资料＋实际外部搜索读取）、**理解与比较**（按当前问题看懂差异，未知保持未知）、**按需深入**（经历依据、知情者入口、准备重点、资源）、**接续探索**（多个主题分别保存候选、依据、私人理由与待问项）、**可信边界**（来源可回原文；失败、中止、冲突如实呈现；私人内容只按明确选择发送给外部 AI）。首版完整场景是选导师（校内外、研究所、海外同一框架），其他机会类型为架构预留，不作首版承诺。

## IA 主张（本稿核心取舍）

1. **两个空间**：公共空间（探索、对象详情、比较、资源与入口）无账号公开浏览；私人空间（我的探索）默认私有，私人理由只归属具体主题的具体候选记录，永不进公共资料。导航不混排。
2. **导航五项**：首页（三入口＋继续上次探索）/ 探索 / 资源与入口 / 我的探索；对象详情与比较是任务内视图，不占顶级导航。命名从"对象类型"（找导师）改为"任务"（探索），因为用户从问题进入而非从对象类型进入。
3. **发现过程是一等对象**：每次外部查找带来自己的问题条件、范围、真实状态（搜索中/读取中/已停止/达到上限）、所得与失败；结果区分"已有资料/本次取得/待查线索"三态。
4. **对象详情按判断顺序组织**：研究什么 → 怎样参与（途径分节、条件分层、状态分明）→ 介绍之外（经历/去向/知情者，缺口如实）→ 未知与待确认；原站、比较、保存全程可达。
5. **比较**：行=问题、列=候选的并排表（沿用 10-24 已确认方向），窄屏连续呈现；不打分、未知不是零分。
6. **主题 = 可恢复的 session**：按最近活跃排序，重开续接上次；双主题严格隔离；改条件不改写私人文字。

## 给后端的目标

发现服务（有范围搜索读取、逐条返回、可中止、有声明上限、失败定位）、公共内容存储（多来源、冲突待核、误合并拆分不伤私人记录）、主题存储（双主题隔离、公共更正只通知不改写）、比较组装（按视角返回依据与未知，不生成分值）、外部 AI 网关（仅发送明确选择内容、发送状态证据含"送达不明"）、全量质量信号（来源/时期/取得时间/核对状态）。详见 design-draft.md 第 7 节。
