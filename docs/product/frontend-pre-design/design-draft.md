## 1. 产品功能全貌

Campus Lumen 是面向大学生个人的**机会探索与决策支持**产品：汇集跨机构、跨地区、跨学科的分散信息，帮助学生发现选项、理解实际内容、比较适配性、按需找到准备重点与资源入口，并在多个并行探索中保留自己的依据和判断。

产品由五组能力构成，对应五类用户成果：

| 能力组 | 用户成果 | 对应需求 |
| --- | --- | --- |
| 发现（复用资料＋实际外部搜索读取） | 从一个模糊兴趣或已知对象得到有来源、有依据的相关选项 | N01–N03、N08 |
| 理解与比较 | 看懂每个选项"实际做什么、怎样参与、条件是什么、差异在哪"，未知保持未知 | N03–N05、N08 |
| 按需深入（经历依据、知情者入口、准备重点、资源） | 介绍之外仍能继续了解；需要准备或资源时找得到适用入口 | N06–N08、N11 |
| 接续探索（多主题保存） | 不同目的的候选、依据、私人理由、待问项分别保存，回来可继续 | N09、N12 |
| 可信边界（来源、状态、异常、隐私） | 每条信息可回原文；失败、中止、冲突、未知都可理解；私人内容只按明确选择发送 | N02、N08、N09、N12 及隐私约束 |

首版完整场景是**选导师**（本校/外校/研究所/海外同一框架；本科进组、短期科研/访问、研究生导师分别表达）。实习、竞赛、交流、活动通知、学习支持等机会类型在需求研究中已覆盖，作为信息架构的预留承载位，不作首版交付承诺。

## 2. 信息架构（IA）

### 2.1 两个空间的划分

整个产品由两个性质不同的空间组成，这是所有页面组织的第一原则：

- **公共空间**：发现、对象详情、比较、资源与入口。无账号、公开浏览，内容是公共资料（人物/团队、研究工作、参与途径、资源、来源）。
- **私人空间**："我的探索"（探索主题）。默认私有，保存在本浏览器；私人理由、待问项只归属具体主题的具体候选记录，永不进入公共资料，不会未经明确选择发送给外部 AI。

导航上不混排：公共空间四个入口，私人空间一个入口。

### 2.2 导航结构（设计判断，非 IA 冻结）

```
Campus Lumen
├── 首页          —— 进入路径选择 + 继续上次探索（无独立宣传职责）
├── 探索          —— 问题输入、外部发现过程与结果（公共）
├── 资源与入口     —— 资源直达查询，可独立结束（公共）
├── 我的探索       —— 主题 session 列表 → 主题工作区（私人）
└── （非导航视图）对象详情、比较 —— 从结果/主题/比较台进入，是任务内视图
```

与"探索→资源与入口→我的探索"的旧建议相比，本稿的取舍与理由：

1. **对象详情与比较不作为顶级导航**：它们是同一任务中的视图（从结果、主题或比较台进入），不是独立必走阶段；导航只放"用户想完成的事"的入口。
2. **首页极简**：只承担三件事——说明这是什么（一句话）、三条进入路径（探索 / 资源直达 / 继续上次探索）、最近主题快捷恢复。不做营销英雄区、不做指标堆叠。
3. **比较是临时工作台**：比较选择是会话内阅读操作，收藏到主题才是持久记录；导航上的比较入口反映"当前比较台有几个对象"，离开不丢已保存内容。
4. 该结构与现行实现（首页/找导师/机会与入口/比较/我的探索）在用户任务层面收敛，但命名与职责按需求重新论证：现行"找导师"入口随场景扩展应为"探索"（问题驱动而非对象类型驱动），现行"机会与入口"归并入"资源与入口"（资源可独立直达是其存在的理由）。

### 2.3 信息对象关系（概念模型，不指定存储/接口）

```
公共侧：
  人物/团队 ──< 研究工作（具体问题、方法、作品入口）
       └──< 参与途径（类型[进组/短访/读研…]、适用身份、时期、条件、状态、原入口）
       └──< 陈述与来源（事实、适用对象、要求性质[硬要求/优先/建议]、
                        原出处、发布时间/适用期、取得/核对时间、核对状态）
       └──< 经历/交流入口（角色、关系、时期、原文、公开/同意依据）
  资源/办理入口（用途、关键前提、费用/权限性质、链接与状态）
  发现过程（发起问题与条件、搜索/读取范围、所得来源、失败项、
            运行/中止/限额状态、时间）

私人侧：
  探索主题（名称、当前问题、可选偏好、关联发现过程）
    └──< 主题内候选记录（引用公共对象＋选定依据时期＋私人理由＋待问项）
    └──< 一次个人内容发送选择（选定内容片段、接收服务、用途、发送状态）
```

关键约束（来自已确认需求，设计不可违背）：
- 同一人物可有多个参与途径，分别表达；院系项目入口不能冒充具名导师招募。
- 硬要求/优先项/建议/历史状态/未知分别表达；未知不显示为不符合。
- 仅同名不合并；冲突保留各版本待确认；公共更正不静默改写私人理由。
- 同一对象在两个主题是两个独立记录，互不影响。

## 3. 页面职责与关键操作

### 3.1 首页

- 职责：让用户 5 秒内知道这是什么、从哪里开始。
- 内容：一句话定位（"汇集跨机构的机会信息，帮你看懂实际内容并自己决定下一步"）；三个进入路径（按问题探索 / 直接找资源与入口 / 继续我的探索）；最近活跃主题（≤3 条，名称＋当前问题＋最近活跃时间）；资料范围与隐私的一句话说明入口。
- 禁止项：无 eyebrow、无副标题堆叠、无渐变英雄区、无虚假指标（"已收录 N 位导师"这类数字若无维护承诺不放首页承诺位）。
- 离开路径：任一进入路径点击即离开；无强制步骤。

### 3.2 探索（发现工作区）

- 职责：T1 从兴趣发现、T2 补查已知对象的主场。
- 内容结构（自上而下）：
  1. **问题输入区**：文本输入（兴趣、对象名或具体问题）＋可选条件（参与目的、机构/地区，可清除）＋"探索"按钮。提交 = 明确要求实际外部发现；仅浏览已有资料不触发联网。
  2. **发现过程状态区**：本次范围（检索词、来源数）、真实状态（正在搜索/正在读取/正在整理/已停止/达到上限，只显示有实际依据的状态，不编造进度百分比）、已得/失败来源分别列出；中止按钮；达到上限时说明原因与已完成范围。
  3. **结果区**：每条结果最少回答——是谁/哪个团队、研究什么具体问题、哪些工作支持、为什么与本次问题相关、已有依据的参与途径。已有资料与本次新获取可分辨（标"本次取得"＋时间）；只取得摘要未读正文的列为"待查线索"，不冒充已确认。
  4. **结果操作**：查看详情 / 加入比较 / 保存到主题（选已有主题或新建）/ 围绕缺口补查。
- 关键规则：搜索途中改条件，旧查找结果仍绑定旧问题并标注，不冒充按新条件筛选；查找可中止，保留部分结果与已存记录；无结果/搜索失败/正文读取失败三种情况分别说明。

### 3.3 对象详情（人物/团队）

- 职责：回答"研究什么 → 怎样参与 → 介绍之外知道什么 → 还需要确认什么"。
- 内容结构：
  1. 研究什么：具体问题、方法简述、代表工作（链接原文）；声明一项合作不代表全部方向。
  2. 怎样参与：按途径分节（本科进组 / 短期科研·访问 / 研究生项目各为一节），每节给出关系、适用身份、时期、条件（硬要求/优先/建议分行表达）、状态（有依据的当前开放 / 已截止 / 未知）、原入口；海外途径的语言考试、签证前提按来源单独标出。
  3. 介绍之外：本人/团队说明、参与者经历（保留叙述者关系与时期）、关系/去向记录（不改写为质量背书）、交流入口（仅公开或经同意的联系方式，注明角色与时期，不保证回复）。材料不足时明确缺口，不编造。
  4. 未知与待确认：来源冲突各版本并列；招募状态未知就写未知。
  5. 常驻操作：打开原站 / 返回 / 加入比较 / 保存到主题——四者在任何滚动位置可达。
- 离开路径：任何一步都可结束；看到原站入口直接离开也算完成任务。

### 3.4 比较

- 职责：按"当前问题"并排呈现两个（或多个）候选的有依据差异。
- 结构：宽屏为一张表——行是比较问题（研究什么/怎样参与/条件/介绍之外/仍需确认），列是候选，同一问题的回答在同一阅读位置；每列保留姓名、机构、依据展开与未知项的补查入口。窄屏按同一问题连续展示各候选，姓名随答案可见。
- 操作：切换视角（研究内容 / 读研途径 / 本科科研·短访）与关注点；从某未知项直接发起补查并回填（用户确认关联后）；写私人理由/待问项并保存到主题；移除比较项（不移除收藏）；返回结果。
- 原则：不打分、不排名；字段缺失显示"未知"而非零分；"某途径不适用"不写成"此人不适合你"。

### 3.5 资源与入口

- 职责：T6 轻任务直达——算力、文献、项目官网、报名入口。
- 内容：用途查询输入；结果只保留用途、关键适用前提、费用/权限性质、来源时间、原入口链接；可申请不等于获批的提示。
- 离开路径：跳转原站即结束；不强制建主题、不生成学习任务。

### 3.6 我的探索（私人空间）

- 主题列表：按最近活跃排序的 session 列表，每行显示名称、当前问题、已保存条数、最近活跃时间；点行进入主题工作区；"返回全部探索"显式离开。重开应用恢复到上次打开的主题（缺失指针时回退）。
- 主题工作区：当前问题与条件（可编辑，编辑不改写候选与私人文字）；候选记录列表，每条含选定依据（带来源与时间）、私人理由、待问项（均可编辑保存）；删除主题需明确确认，说明只影响本主题。
- 对外 AI 边界（采用模型时的目标界面）：发送前显示本次选中的具体内容片段、接收服务与用途；发送状态与选择分开——"尚未发送 / 已发送等待结果 / 已返回 / 发送状态未确认，可能已发送"；取消后不再附带，重试前可核对当前选择与前次状态。

## 4. 用户进入与离开路径（任务流）

| 任务流 | 进入 | 关键操作 | 自然结束位置 |
| --- | --- | --- | --- |
| T1 从兴趣发现 | 首页/探索，输入模糊兴趣 | 看已有资料＋本次外部所得 → 读详情 | 看见一个有意思的方向即可离开；也可保存或比较 |
| T2 补查已知对象 | 探索，输入姓名/对象 | 查看依据 → 按需补查 → 确认关联保存 | 得到答案，或明确"仍待确认"即可离开 |
| T3 比较候选 | 详情/结果"加入比较" | 选视角阅读差异 → 写理由保存 / 对未知补查 | 保留、排除、换目标或不作决定均可结束 |
| T4 进一步了解与准备 | 详情"介绍之外/准备" | 看经历/联系入口/准备重点 → 留待问项 | 打开入口、留下一个问题或决定暂缓即结束 |
| T5 保存并恢复 | 任意保存操作 / 我的探索 | 保存到主题 → 关闭 → 重开恢复 | 改条件、移除候选、删除主题或继续 |
| T6 资源直达 | 资源与入口 | 查用途与前提 → 打开原站 | 跳转即结束，无需任何前置步骤 |

所有流程允许跳过、回退、从中间进入；没有一条"必须先完成"的链路。浏览、保存、符合资格都不等于承诺参与。

## 5. 典型场景页面内容样例（设计样例）

**场景：AIDS 学院学生，兴趣"AI 系统"，比较暑研与长期读博两条线。**

- 探索输入："想了解 AI 系统方向的研究，暑期能做什么"→ 结果区出现既有候选（如"江祖铭 · 香港大学 · 系统/安全/数据库，博士与 RA 招募说明，2026-10-12 取得"）与本次新读取来源（标"本次取得 10:32"），另有 1 条"待查线索：仅取得搜索摘要，未读到正文"。
- 详情"怎样参与"节：短访途径——"有院系联合培养说明（来源：学院页面，2026-05 发布），本人是否接收外校本科生：未知"；每条途径右上是原站链接。
- 比较表行"暑期参与可能"：A 列"有 RA 招募表述，当前名额未知"，B 列"未读到短期参与说明——未知（可补查）"。
- 主题"暑期研究"中该候选的私人理由："方向靠近 GPU 加速，想确认暑期时长要求"；同一候选在"长期导师探索"主题中理由为"系统+安全交叉，待确认博士名额"——两条理由互不干扰。
- 资源直达：查"算力"→ "科大超算：面向课题组的计算资源，需导师课题账号申请（来源：注册页，2026-09 查看）→ 打开原站"。

## 6. 需求追溯：N 编号 → 页面/交互/用户成果

| 需求 | 落点 | 用户可检查的成果 |
| --- | --- | --- |
| N01 模糊进入、可改条件 | 探索输入区＋主题条件编辑 | 不填画像即可开始；改条件不丢已保存候选 |
| N02 实际外部发现 | 发现过程状态区＋结果区来源标注 | 来源、相关原因、覆盖范围可见；失败/中止/上限可理解并可继续 |
| N03 人物-研究-途径-资源关联 | 对象详情分节＋原站入口 | 同一人物不同途径分开；可回原文 |
| N04 条件分层解释 | 详情/比较的条件行 | 优先不当门槛；海外前提单独标出 |
| N05 按问题比较 | 比较视图 | 关键差异与未知可读；缺资料不等于差评 |
| N06 按需准备 | 详情"准备"＋按需展开 | 需要者知道从哪开始；有基础者可跳过 |
| N07 资源查找 | 资源与入口 | 用途/权限/费用清楚；可申请≠获批 |
| N08 状态与入口区分 | 途径状态标注＋历史标记 | 历史资料有帮助但不冒充当前开放 |
| N09 多主题接续 | 我的探索 session 列表与工作区 | 双主题各自保存恢复；互不影响 |
| N11 经历与知情者 | 详情"介绍之外" | 保留关系/时期/来源；无材料显缺口 |
| N12 整理纠错 | 公共资料维护流程（对前端：冲突/待核展示） | 已知错误可修；误合并可拆且私人记录保留 |
| N10/N13 | 不在首版 | 编号保留，未来采纳时再启用 |

## 7. 给后端的实现目标（能力清单，不含技术选型）

前端目标体验要求后端最终提供以下能力与状态；本轮不锁定接口路径、数据库或工具：

1. **发现服务**：接收公开查询/指定 URL，执行有范围的外部搜索与正文读取；逐条返回所得正文与完成范围；支持中止；执行声明的时间/来源数/费用上限；返回失败位置（搜索失败 vs 正文读取失败）与部分结果；迟到结果不写入已中止任务。
2. **公共内容存储**：人物/团队、研究工作、参与途径、陈述与来源、经历/交流入口、资源的结构化存储；同一对象多来源、多版本冲突与待核状态的表达；重复来源去重；误合并拆分修复且不触碰私人记录。
3. **主题存储**：主题（问题、条件）与主题内候选记录（引用公共对象＋私人理由＋待问项）的持久化；双主题隔离；公共更正下发为"事实变更通知"而非改写私人理由。当前 demo 的 localStorage 边界如实声明，扩展存储时另行记录保存/删除行为。
4. **比较组装**：按指定候选集合与视角返回各比较行的依据、来源与未知项；不为缺失字段生成分值。
5. **外部 AI 网关（采用模型时）**：请求组装只含用户本次明确选择的个人内容＋任务所需公共依据；维护发送状态证据（未发出/等待/返回/送达不明）；支持取消后续附带；输出归属对应私人主题。
6. **质量信号**：所有事实带出来源、发布时间/适用期、取得/核对时间与核对状态，前端据以渲染"历史/未知/冲突"。

## 8. 设计判断与边界声明

- **已确认需求**（不属设计自由裁量）：两个空间分离、途径分别表达、条件分层、未知如实、中止/上限、误合并修正、个人内容选择发送与送达不明、多主题隔离、轻任务直达——以上来自需求基线 v1.0 与用户已确认决议。
- **本稿的设计判断**（可评审修改）：导航五项的具体命名与数量、比较采用"行=问题/列=候选"的表格组织（用户 10-24 已指定双对象并排方向，本稿沿用）、主题按 session 列表组织与续接指针、首页三入口结构、结果区"本次取得/已有资料/待查线索"三态标注。
- **未来可选扩展**（本稿预留但不承诺）：通知订阅（N10）、已有要求自动进度（N13）、社区共同维护、账号与跨设备同步、更多机会类型的完整流程。
- **本稿未做**：接口路径/数据库/模型选型（留技术设计）；任何"尚未实现"功能的演示承诺；学生收益的量化和断言。
