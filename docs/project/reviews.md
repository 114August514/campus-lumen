## 2. 评审证据的限制

1. 多数代码评审由 AI reviewer 执行；AI 是工具，不是课程团队成员，也不能代替真实用户或教师判断。
2. PR #12 的日志明确 GitHub 没有 submitted review / review thread；本地只读评审虽可追溯，但协作平台上的批准链不完整。
3. 页面评审使用的截图多位于 `/tmp` 或 ignored `work/`，没有作为版本化附件归档；因此只能引用日志中的检查范围，不能声称仓库保存了完整视觉证据。
4. CI 证明指定检查通过，不证明内容正确、用户收益、可访问性完整或未覆盖路径无缺陷。

## 4. 建议评审记录格式

后续每次评审至少记录以下字段，避免把“测试通过”写成“评审通过”：

| 字段 | 要求 |
| --- | --- |
| 对象 | PR / commit / 文档版本 / 页面与环境 |
| 评审者 | 人类姓名或 AI 工具名称；注明是否为构建者 |
| 方法 | 阅读范围、走查步骤、使用的检查与未覆盖项 |
| 发现 | 阻塞 / 非阻塞、证据位置、是否复现 |
| 处理 | 修复 commit、接受风险、驳回理由或待办 owner |
| 结论 | 通过、附条件通过、不通过；不得用 CI 状态代替 |
