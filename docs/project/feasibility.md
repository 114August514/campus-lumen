# 可行性分析报告

Last updated: 2026-10-29

状态：中期分析。本文汇总现有证据，不把尚未执行的测试、未测收益或法律开放项写成结论。范围与验收分别见[需求分析](../product/requirements-handoff.md)和[中期验收标准](acceptance.md)。

## 1. 项目与分析边界

Campus Lumen 面向大学生个人，将跨机构机会资料组织为可追溯、可比较、可接续的探索。中期 demo 要让所有机会类型共用“探索 → 发现 → 处理”流程；选导师内容最深，其他类型沿用现有整理入口，不新增调研采集。依据见[前端设计](../product/frontend-design.md)和[需求范围](../product/requirements-handoff.md)。

可行性只回答在中期约束下能否演示，不证明普遍需求、实际节时、录取收益或长期服务能力；这些限制沿用[需求分析](../product/requirements-handoff.md)。

## 2. 技术可行性

- 前端已有 React/Vite、Primer、同源 `localStorage` 多会话保存和来源展示；后端已有 Rust/Axum 公开页面发现与流式进度，OpenAPI 可生成 TypeScript 客户端。当前运行结构见[概要设计](../architecture/overview.md)。
- 发现服务已有明确边界：服务端整轮 30 秒、最多 5 个正文、6 次读取、48 次 HTTP 请求，每次读取 14 秒/1 MB；客户端等待 35 秒，进程并发 2。详见[API 契约](../architecture/api-contracts.md)和[需求规格](requirements-spec.md)。
- 官网直读已用于真实公开页面；关键词搜索可能遇到反爬验证页，这是已知技术风险。服务只处理允许范围内的公开静态 UTF-8 HTML，不承诺读取 PDF、登录后页面或依赖 JavaScript 渲染的页面，见[安全边界](../operations/security.md)。现场因此以 `jzuming.github.io` 官网直读作为实时步骤，失败时如实显示，不用回放冒充成功。
- 中期 AI 整理采用本地“模拟整理服务”，明确标注模拟、不调用真实模型、服务端不持久化内容。它可验证选择发送、等待、返回和送达不明的产品行为；不能证明真实模型的质量、费用或供应商数据处理条件。真实模型接入后置，见[前端设计](../product/frontend-design.md)。
- 主要技术风险仍包括：现场网络波动、反爬验证、单页前端重构范围、浏览器存储依赖固定 origin，以及尚待执行的完整浏览器走查。缓解与退出条件见[项目进度](progress.md)和[验收计划](acceptance.md)。

**判断：**本地中期演示在当前技术栈上可行；公网关键词发现和真实模型集成不具备同等确定性，不能作为无降级说明的现场前提。

## 3. 数据与来源可行性

- 已有 7 位导师、3 个实习候选和 26 条跨 8 类机会／入口资料，可支持有限演示；数量来自[项目进度](progress.md)，不代表全量覆盖或持续更新。
- 公开官网、院系／课题组页面、项目入口和已审查批次可支持来源、时间、历史状态与未知项展示。固定批次、实时读取、整理摘要和待查线索必须分别标识，规则见[需求分析](../product/requirements-handoff.md)。
- 指导经历供给不均，目前没有可交付的具名独立指导经历样本；中期以“缺口＋待问事项＋公开了解路径”表达即可，不用 AI 编造，见[需求分析](../product/requirements-handoff.md)。
- 历史招募只能帮助认识方向，不得显示为当前开放；冲突与身份不明保留待核。数据质量与纠错要求见[需求规格](requirements-spec.md)。

**判断：**资料足以支持有边界的中期流程演示，不足以支持全面覆盖、实时开放状态保证或具名对象质量评价。

## 4. 经济与成本可行性

- 中期 demo 本地运行，不调用收费模型或收费搜索 API；发现使用公开页面读取，AI 使用模拟服务。依据见[开发运行说明](../engineering/development.md)和[API 契约](../architecture/api-contracts.md)。
- 仓库没有经核对的开发人时、设备、托管、真实模型调用或长期维护成本估算，也没有量化收益数据；因此不能给出成本效益比或长期预算结论。
- 现阶段新增直接运行成本主要是已有开发机、网络和现场演示环境；这不是“零成本”声明。若改为公开部署、真实搜索供应商或真实模型，必须另行估算调用、托管、监控、内容核对和异议处理成本。

**判断：**在“不调用收费模型或搜索 API、仅本地演示”的中期边界内经济上可执行；持续服务的成本可行性仍是开放项。

## 5. 运行与维护可行性

- 演示采用两个本地进程：Axum API 与 Vite Web；固定从 `http://127.0.0.1:5173` 打开。浏览器数据只在同一浏览器 profile 和同一 origin 下恢复，换 host、端口、浏览器或 profile 都不保证迁移，见[用户手册](user-guide.md)。
- API 对探索会话无服务端持久化；个人会话在浏览器 `localStorage`。不存在账号、跨设备同步、项目托管备份或用户导出，见[隐私文档](../product/privacy.md)。
- 当前内容纠错可走仓库文件流程，但长期负责人、更新周期、服务级别、异议入口、备份和公开部署均未确定。[运维概览](../operations/overview.md)和[部署说明](../operations/deployment.md)中的生产清单是未来条件，不是中期已具备能力。

**判断：**单机、单浏览器的现场演示可运行；长期公开运营和多人维护尚不可判定可行。

## 6. 法律、隐私与社会分析

本节是风险分析与待办，不构成法律意见或合规结论。

- **个人信息处理：**具名导师等职业公开信息仍可能属于个人信息。当前以展示来源、时间、用途、纠错能力和最少必要内容降低风险；具体处理依据、告知要求、权利响应流程和适用法律仍需在公开发布前由有资质人员确认。
- **个人内容：**私人理由、待问和决定默认只在浏览器保存。只有用户在发送确认中逐条勾选的片段可以进入模拟整理请求；不得记录私人原文。完整边界见[隐私文档](../product/privacy.md)。
- **版权与转载：**官网正文、摘要、截图或平台帖子可能受版权保护。中期应只展示任务所需的有限节选、作者／标题／URL／取得时间，并引导回原站；“公开可访问”不等于取得再发布授权。批量保存、公开发布或长期缓存前需核对授权、合理使用边界及删除机制。
- **平台条款与 robots：**小红书、Bilibili 等材料来自应用外的开发试采，不等于应用获准自动采集。不得绕过登录、验证码、访问限制或复用第三方凭据；自动化前须核对平台条款、robots 和账号使用边界。
- **社会影响：**不对导师或机会做人格评分、黑红榜或无依据背书；未知不按负面处理；浏览、保存或符合条件不构成参与义务。原则见[需求分析](../product/requirements-handoff.md)。
- **开放项：**公开发布前还需确定内容更正／异议联系人、个人信息处理依据、版权与平台条款审查、真实 AI 服务的数据保留与删除条件。

## 7. 进度可行性

[项目计划](progress.md)把 2026-10-29 至 10-31 分为整合与文档、页面与测试、浏览器走查与报告三段，并明确由协调者负责整合与验收。中期范围以 M1–M4 的完整演示为最低门槛，其他失败项写入测试报告，不以缩小测试范围换取“通过”。

排期风险主要来自前端重构、并行分支整合和完整走查尚未执行。本文不根据计划表推断已完成；实际结果以[测试报告](test-report.md)为准。

## 8. 方案比较

复用[需求论证的五种方案](../product/needs-analysis.md)：

| 方案 | 优点 | 主要限制 | 中期取舍 |
| --- | --- | --- | --- |
| 原站＋搜索／AI＋笔记 | 无需建设新产品，灵活 | 跨来源关联仍由个人承担，负担未测 | 保留为有效替代与对照 |
| 入口导航 | 适合单次查询，维护相对简单 | 不能独立解决深度比较 | 纳入资料库和轻任务终点 |
| 精选机会资料库 | 便于发现、查看条件与原文 | 选源、去重、更新有成本 | 作为已有资料基础，不以数量宣称价值 |
| 有限资料＋按需关联比较 | 支持发现、比较、来源与私人判断 | 解释和关系维护成本更高，资料可能不完整 | **当前采用**；所有类型共用流程，导师内容最深 |
| 全平台自动推荐＋推送／进度 | 假设可支持持续跟踪 | 数据、个性化、权限、运营和返回需求均不足 | 中期不采用 |

## 9. 风险与结论

| 风险 | 当前处理 | 残余未知 |
| --- | --- | --- |
| 关键词搜索触发验证页 | 演示使用官网直读；失败如实呈现 | 不保证任意关键词成功 |
| 资料过时或冲突 | 标时间、历史／未知，保留多版本 | 长期更新责任未定 |
| 私人内容误发 | 默认不选、逐条勾选、请求回显、不记录正文 | 真实外部服务规则未选 |
| 模拟被误认成真实 AI | 服务与结果显著标“模拟” | 不能验证真实模型质量 |
| 本地存储丢失 | 固定浏览器/profile/origin，演示前准备合成会话 | 无备份、同步、导出 |
| 版权、条款、个人信息 | 有限节选、来源链接、不绕过限制 | 公开运营前仍需专业审查与流程 |
| 进度与整合 | 按验收最低项收敛、失败入报告 | 完整走查尚待执行 |

**结论：**在本地演示、有限公开资料、官网直读和明确标注的模拟 AI 边界内，中期方案技术上和短期运行上可行，数据足以支持有限演示。经济效益、公开部署、长期维护、真实模型、版权／平台条款及个人信息处理的正式结论均未建立，不能由中期 demo 外推。
