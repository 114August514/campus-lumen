# 中期验收标准与测试计划

Last updated: 2026-10-31

状态：v1.0，2026-10-29 与用户确认的中期检查口径。验收对象是集成分支 `feat/midterm-demo` 上的 demo；需求来源为[需求分析 v1.0](../product/requirements-handoff.md) §7–§8 与[任务设计 v0.4](../product/advisor-task-design.md) §6–§7。执行结果写入[测试报告](test-report.md)。

## 0. 判定规则

- **最低验收（M）**：用户指定。前端完整展现 demo 的最终期望形态，全部 M 项通过才算中期 demo 达标。
- **功能（F）、质量（Q）、工程（E）、文档（D）**：逐条判定为通过、未通过或部分通过，未通过的项如实写入测试报告，不以预先整理的结果替代。
- 每条注明验证方式：
  - `自动`：单元/组件测试或 CI；
  - `走查`：浏览器实际操作，测试报告记录步骤、结果和截图位置；
  - `实时`：至少一次真实外部读取；
  - `模拟`：使用界面上明确标注的模拟服务、回放或合成数据。模拟项只验证处理规则，不代替实时项。
- 通过只表示这些行为能运行，不代表已证明普遍需求、节时效果或长期维护能力（沿用需求 §8.2）。

| F03 | 发现状态如实显示：进行中、已完成、已中止、达到上限、失败。中止后保留已收到的正文，迟到返回不写入已中止的任务 | N02，§7.3 | 自动、模拟（回放） |

| F09 | 有经历记录时呈现角色、时期和来源；没有时显示缺口与待问事项，并给出可了解的公开途径；不评价导师品质 | N11，§8.2 进一步了解 | 走查 |

## 6. 不在中期验收内

- 学生试用收益、跨设备同步、部署上线、长期维护承诺；词元计划输出质量也未测量。
- 具名的独立指导经历样本。按需求 §8.1 的现状，以缺口和待问事项呈现即可达标。
- 为导师和实习以外的类型新增调研采集。这些类型走同一流程，内容深度沿用现有 26 条入口资料，只验证流程可复用（F18）。
